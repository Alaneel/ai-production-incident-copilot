1. Check the install (runs a read-only diagnosis and confirms a reader cannot approve):

   helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

2. Reach the API{{ if .Values.orchestrator.console.enabled }} and its console (same port){{ end }}:

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ $api }} 8080:8080
   export OPSPILOT_READER_TOKEN=$(kubectl -n {{ .Release.Namespace }} get secret {{ $secret }} -o jsonpath='{.data.orchestrator-read-token}' | base64 -d)
{{- if .Values.orchestrator.console.enabled }}

   Open http://localhost:8080 and, under "API connection", confirm the
   backend and paste the reader token (echo $OPSPILOT_READER_TOKEN). The page
   keeps tokens in memory only. Over a network it sends them only to HTTPS.
{{- end }}

3. Connect an agent (diagnose and read only; no tool can approve):

   claude mcp add --transport http opspilot http://localhost:8080/mcp \
     --header "Authorization: Bearer $OPSPILOT_READER_TOKEN"

4. Send alerts: point an Alertmanager webhook receiver at
   http://{{ $api }}.{{ .Release.Namespace }}.svc:8080/v1/incidents/alerts/alertmanager
   with the same bearer token{{ if and .Values.networkPolicy.enabled (not .Values.networkPolicy.ingressNamespaces) }}, and add Alertmanager's namespace to networkPolicy.ingressNamespaces{{ end }}.

Approvals need the operator token (key orchestrator-operator-token), which
records "{{ .Values.auth.operatorActor }}" as the approving actor. Keep it with your on-call engineers.
{{- if .Values.orchestrator.console.enabled }}
To approve in the console, enter that token and "{{ .Values.auth.operatorActor }}" as the operator actor.
{{- end }}
