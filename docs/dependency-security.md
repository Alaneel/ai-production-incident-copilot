## Remaining unfixed build advisory: conditionally mitigated

Final native `npm audit` reports **eight High inherited package records, zero Critical/Moderate/Low**. These eight records reduce to one vulnerable package/advisory: `braces 3.0.3`, [CVE-2026-93687 / GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). The reviewed affected range is <= 3.0.3, no patched version is listed, and the official registry's latest remains 3.0.3. The vulnerable upstream package has not been declared fixed. `fflate 0.8.3` removed its separate malformed-ZIP finding; forced npm suggestions to downgrade Next/Vinext were rejected.

Observed call paths:

- `eslint-config-next → @next/eslint-plugin-next → fast-glob`: `get-root-dirs.js` derives patterns from repository lint settings.
- `vinext → vite-plugin-commonjs → vite-plugin-dynamic-import → fast-glob`: the Vite transform's `globFiles` derives patterns from source AST import expressions and configured extensions.
- `fast-glob` calls `micromatch.braces(pattern, {expand:true})`; micromatch invokes braces' recursive compile/expand walkers.

Those inputs are repository source/configuration at build or lint time. Application request handlers expose no glob/build input endpoint. The [release build guard](../build/release-bundle-boundary.ts) refuses these five build-tool packages in every emitted chunk's modules and external/dynamic imports. It also checks nested and Windows paths; [regressions](../tests/release-bundle-boundary.test.mjs) cover each denied package. The actual production build and lexical bundle scan show no such runtime package references.

Local maintainer builds use reviewed source and a loopback development server. Pull-request CI can execute untrusted fork source: ephemeral disposable runners, read-only permissions, no provider/deployment secrets and a 20-minute job timeout bound its residual denial-of-service exposure. An untrusted contributor can still exhaust or fail their isolated build job; braces remains affected. The production graph guard verifies the current reviewed bundle, not an arbitrary fork. Do not provide remote builds or pattern processing to untrusted users. If that boundary changes, this disposition becomes a release blocker. Future upstream fixes must be reviewed and locked rather than suppressing advisory output.

## Security coverage and limits

A complete graph export to OSV was rejected by automatic approval review; it was not executed or retried. Current validation uses the authorized native npm result and local checks. An independent offline comparison of 695 graph records/686 unique versions against the previously retrieved primary advisory cache found 150 affected rows no longer matching final versions, two removed, and only braces still matching; it had no comparison errors. This establishes closure of prior findings, not absence of newly published advisories. The independent fresh local Trivy database scan covered all 686 unique graph versions: 617 npm versions (one High braces match), 68 actual third-party Python distributions (zero matches), and one actual compiled Go 1.26.9 stdlib SBOM entry (zero matches). No graph metadata was exported. The raw Mach-O filesystem scanner is unsupported and is not reported as passing; the Go SBOM is derived from actual binary build metadata plus the verified absence of third-party modules. Container OS/native/image scans remain separate gates.

Package version matches and npm inherited records are different units and do not prove exploitability. No global severity downgrade or zero-vulnerability claim is made. The container OS/native library, host runtime and provider platform scopes require their own evidence; static package scans do not prove application authorization or model safety. Keep [local development boundaries](../SECURITY.md), [API authorization](api-authorization.md), and the explicit production gaps in the README.
